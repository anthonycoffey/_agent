# Bugsy — Project Context for Claude

## What Is This?

**Bugsy** is Anthony Coffey's personal AI agent stack, running 24/7 on a GCP Compute Engine VM.
The goal: automate the repetitive parts of freelance dev life — job hunting, lead gen, outreach,
research — and build a personal knowledge base that makes every AI interaction smarter over time.

Bugsy has a persona: 1970s New York Italian mobster. Calls Anthony "boss." The persona wraps
useful output — it's flavor, not noise. Don't let it swallow the actual content.

**Anthony's experience level:** Newer to infra and agents. Explain concepts when something
unexpected happens, not just steps. He's a capable developer but GCP/Docker/n8n patterns
are still being internalized.

|---|---|

| Name | `agent-vm` |

| Managed by | Terraform (`tf/`) |

Cloud-init bootstraps the VM on first boot only. Any changes after that require
`git pull` on the VM and manually re-importing n8n workflows (n8n stores its own
copy of each workflow in postgres — file changes don't auto-apply).

### Networking

- **No public IP.** VM is unreachable from the internet directly.
- **Cloudflare Tunnel** (`cloudflared` container) provides all public ingress. Outbound-only.
- **Tailscale** for SSH access from Anthony's machines. SSH as `agent@agent-vm`.
- Public subdomain: `n8n.coffey.codes` (via Cloudflare Tunnel → n8n container port 5678)

## Vector Store (Qdrant)

**Collection:** `personal_knowledge`
**Model:** `nomic-embed-text` (768-dimensional, Cosine similarity)
**Purpose:** RAG over Anthony's personal documents — resume, writing samples, case studies,
project history. Used as context injection for cover letter drafting, outreach writing, etc.

**Payload schema per point:**
```json
{
  "text": "chunk content",
  "title": "document title",
  "category": "bio | articles | case-studies | projects",
  "tags": ["tag1", "tag2"],
  "chunk_index": 0,
  "total_chunks": 5,
  "ingested_at": "ISO timestamp"
}
```

**Ingesting documents:**
1. Drop markdown files (with YAML frontmatter) into `~/agent/rag/<category>/`
2. Run `bash ~/agent/rag-ingest.sh` (or `bash ~/agent/rag-ingest.sh bio` for one category)
3. Files are POSTed to the RAG Ingest webhook and embedded automatically

**Frontmatter format:**
```markdown
---
title: My Resume
tags: [resume, react, node, typescript]
---

Content here...
```

## Key Architectural Decisions

- **No public IP** — Cloudflare Tunnel only. VM unreachable from internet directly.
- **`~/agent` is a git symlink** — cloud-init only runs once; git pull is the deploy mechanism.
- **GCE cloud-init requires plain-text user-data** — `gzip=false, base64_encode=false` in Terraform.
- **OS Login conflicts with cloud-init `users:` block** — use `bootcmd` to create users instead.
- **Docker bind mounts fail silently if source is missing** — missing source gets auto-created as
  a root-owned directory. Always commit the real file, or use `bind.create_host_path: false`.
- **n8n Code node sandbox has no HTTP primitives** — `fetch` and `$helpers.httpRequest` are
  unavailable. Use `axios` via `NODE_FUNCTION_ALLOW_EXTERNAL=axios`.
- **n8n `docker ps` showing `Up` ≠ healthy** — cross-check with `docker logs` and
  `docker inspect ... .State.RestartCount`.
- **Bind mounts are negotiated at container *create* time** — after fixing a host file/dir
  confusion, `docker compose restart` is not enough; use `docker compose rm -sf <svc> && up -d`.

## How to Deploy Changes

### Code / config changes
```bash
# On the VM
cd ~/bugsy && git pull
cd ~/agent && docker compose up -d <service>   # if docker-compose.yml changed
```

### n8n workflow changes
1. Push JSON changes to GitHub
2. In n8n UI → open workflow → ⋮ → Import from URL:
   `https://raw.githubusercontent.com/anthonycoffey/_agent/main/agent/n8n/workflows/<file>.json`
3. Save → activate

### Terraform changes
```powershell
# From Windows dev machine in tf/
terraform plan
terraform apply
# Force VM replacement if needed:
terraform apply "-replace=google_compute_instance.agent"
```

### Known Issues / Gotchas
- Many job board source sites have blocked the VM IP from scraping — job listings are stored
  but direct access to those sites from the VM may be blocked. Applying to jobs should be done
  from a personal machine, not routed through Bugsy.
- n8n workflow changes must be manually re-imported — there is no auto-sync between the repo
  and the running n8n instance.
- Job board UI status (reviewed/dismissed) is persisted in browser `localStorage` — it won't
  sync across devices.
