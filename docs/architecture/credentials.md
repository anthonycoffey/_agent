# Credentials & secrets

## Where secrets live

- **`agent/.env`** — generated by Terraform on VM bootstrap. Contains `POSTGRES_PASSWORD`, `WEBUI_SECRET_KEY` (LiteLLM bearer), `N8N_ENCRYPTION_KEY`, `EVOLUTION_API_KEY`, etc. Loaded automatically into containers via `docker compose`. Also auto-loaded into the SSH login shell.
- **n8n credential store** — n8n encrypts API credentials (Slack, Postgres connection, LiteLLM Bearer, etc.) in its Postgres DB. Encryption key is `N8N_ENCRYPTION_KEY` from `.env`. **Never commit this; never let it rotate accidentally — losing it means re-creating every credential.**
- **Terraform state** — held in a GCS backend (configured in `tf/`). Controls `.env` value generation.

## n8n credential gotcha

n8n's task runner sandbox blocks both `process.env` and `$env.VARNAME` inside Code nodes. Any workflow that needs a secret must:

1. Define it as a credential in n8n's UI (e.g. `Header Auth`, `Postgres`, `Slack API`)
2. Attach the credential to a **native node** (`HTTP Request`, `Postgres`, `Slack`) — not a Code node

The bearer token for LiteLLM is stored as a `Header Auth` credential named `LiteLLM Bearer` and referenced by `Authorization: Bearer <value>` on the relevant HTTP Request nodes. See [`workflows/bugsy-unified.md`](../workflows/bugsy-unified.md) for the full pattern.

|---|---|---|
| `Slack - Bugsy` | Slack API | `bugsy.json`, `bugsy-events`, `bugsy-inbox-watcher`, `bugsy-job-board-fetcher`, `bugsy-leads-hunter`, `bugsy-research` |
| `LiteLLM - local proxy` | OpenAI API | LangChain `openAi` nodes — `bugsy.json`, `bugsy-chat`, `bugsy-events`, `bugsy-inbox-watcher`, `bugsy-leads-hunter`, `bugsy-research`, `bugsy-whatsapp` |
| `LiteLLM Bearer` | Header Auth | Raw HTTP calls to LiteLLM — `bugsy-job-board-fetcher`, `bugsy-rag-query` |
| `Postgres — agent DB` | Postgres | App data — `bugsy-job-board-fetcher`, `bugsy-job-board-ui`, `bugsy-leads-hunter` |
| `Postgres - Memory database` | Postgres | LangChain Postgres Chat Memory — `bugsy.json`, `bugsy-events` |
| `Gmail - Bugsy (anthony@coffey.codes)` | Gmail OAuth2 | `bugsy-inbox-watcher`, `bugsy-research` |

Credential IDs are referenced inside the workflow JSON files. If you re-create a credential, you must also update the JSON to point at the new ID (or re-pick it from each node's credential dropdown in the n8n UI).

The same `LiteLLM - local proxy` credential is reused everywhere a LangChain `openAi` node is used. The bearer-auth variant (`LiteLLM Bearer`) exists for raw `HTTP Request` nodes that hit `http://litellm:4000/v1/chat/completions` directly — they can't use the OpenAI-API credential type. Both wrap the same underlying `WEBUI_SECRET_KEY` value from `agent/.env`.
